# Publication boundaries

## Visibility recommendation

Use this repository as a public, concept-only project showcase. Keep proprietary implementation in a separate private repository. If unpublished strategy is added later, keep that work private until it has been reviewed for disclosure.

## Suitable for this repository

- High-level problem statements and product principles.
- Proposed milestones and clearly labeled limitations.
- Synthetic examples and reviewed interface sketches.
- Research summaries that can be shared and properly attributed.

## Omitted from this repository

- Proprietary architecture, algorithms, internal schemas, and implementation strategies.
- Credentials, tokens, private keys, environment files, and production configuration.
- Real identity records, user exports, private conversations, and confidential research.
- Commercial agreements, partner details, and unpublished business plans.

A private directory inside a public repository is still public if committed. Keep sensitive work outside this repository. Ignore rules are only an accidental-add safeguard, not access control.

## Before each publication

Review the staged files and history, use fictional data, remove unsupported claims, and check that screenshots do not expose private information. Choose licensing deliberately before adding reusable source code.
